# Project Architecture

## Library
* **UI 프레임워크:** React 18 (Vite 환경)을 사용하여 화면을 구성한다.
* **차트 및 데이터 시각화:** Recharts 라이브러리를 사용한다. (Zone B의 Line, Bar, Pie 차트 구현 시 반드시 사용)
* **아이콘:** (향후 필요 시 lucide-react 등 일관된 라이브러리를 사용한다)
* **스타일링:** Tailwind CSS만을 엄격하게 사용하며, 불필요한 인라인 스타일이나 프레임워크 혼용을 절대 지양한다.

## Directory Structure
| 경로 | 역할 |
| :--- | :--- |
| `/data` | 과제 요구사항에 따른 Mock 데이터 파일(.json 또는 .ts) 위치 |
| `/src/components` | Card, Chart, Table 등 재사용 가능한 개별 UI 컴포넌트 |
| `/src/pages` | Zone A, B, C를 모아두는 전체 대시보드 페이지 레이아웃 |
| `/src/types` | TypeScript Interface 및 Type 정의 파일 |
| `/src/utils` | 날짜 변환, 숫자 포맷팅(콤마 찍기 등) 공통 유틸리티 함수 |

## Convention (코딩 규칙)
* 컴포넌트는 함수형(Functional Component)으로 작성하며 화살표 함수를 사용한다.
* 모든 데이터와 Props는 명확한 TypeScript Interface를 정의하여 타입 안정성을 보장한다.
* 하드코딩을 엄격히 금지하며, 화면에 표시되는 지표 수치와 차트 제목 등은 전달받은 상태(State)와 데이터를 기반으로 동적 렌더링한다.

## Global State & Data Flow (전역 상태 및 데이터 흐름)
* **상태 끌어올리기 (Lifting State Up):** 기간 필터(전체 / 오늘 / 7일 / 30일) 같은 전역 상태는 반드시 최상단 부모 컴포넌트(`Dashboard.tsx`)에서 관리한다.
* **단방향 데이터 전달:** 하위 컴포넌트(차트, 테이블)는 데이터를 직접 import 하거나 가공하지 않고, 부모로부터 필터링된 배열을 `props`로 전달받아 순수하게 렌더링만 수행한다.

## AI Behavior (AI 동작 및 소통 규칙)
1. **대규모 수정 시 확인:** 3개 이상의 파일을 동시에 수정하거나, 기존 아키텍처를 크게 변경해야 하는 경우 코드를 즉시 작성하지 말고 반드시 사용자에게 먼저 허락을 구한다.
2. **코드 모듈화:** 하나의 파일에 모든 코드를 때려 넣지 말고, 컴포넌트나 유틸리티 기능별로 적절히 모듈화(분리)하여 작성한다.
3. **추론 금지:** 사용자의 요청이 모호하거나 명확하지 않을 때는 임의로 추론하여 코드를 실행하지 않는다. 반드시 "제가 이해한 바가 맞는지" 먼저 질문하여 의도를 확인한 후 작업을 시작한다.
